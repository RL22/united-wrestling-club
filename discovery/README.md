## Sharding and archive (2026-11-08)

- **Sharding.** Any doc over 250 lines is split on its `##` headings. The original path becomes an index file: frontmatter, a TL;DR, and a Parts table. The full text sits in a folder with the same name, as `NN-<section>.md` parts. Each part keeps the text verbatim, and only its links were rewritten. Cite the part file when you can. Ledger claims point at the part that holds the quote.
- **Stale details.** A passage that states a fact changed on 2026-11-07 is replaced in place with a one-line `Superseded` note. The old text moves to [`archive/stale-2026-11-08/`](archive/stale-2026-11-08/README.md), with the source path and the reason.

## Machine-readable layer

- **`ledger/claims.json`** is generated by `python3 scripts/ledger_build.py <shard files> --conflicts <file>`. Each claim has `id` (CL-NNNN), `topic`, `claim`, `value`, `source`, `section`, `evidence` (a verbatim quote), `doc_status`, `doc_date`, `verification`, `kb_id`, and `conflicts_with`. `scripts/ledger_check.py validate <file> --final` checks that every evidence quote appears verbatim in its source file.
- **`ledger/topics.json`** is written by the same build. It is the router from topic to docs.
- **`manifest.json`** lists every library doc with its type, status, owner, dates, and source count. Regenerate with `python3 scripts/discovery_check.py manifest`.
- **Folder `README.md` files** under `client/`, `site/`, `strategy/`, `market/`, `brand/`, and `archive/` are generated by `python3 scripts/discovery_check.py index`. A hand-written README is never overwritten.
- **`python3 scripts/discovery_check.py check`** enforces frontmatter, the lifecycle, naming for call notes, and broken links (errors). It also warns about missing sources, stale review dates, and missing TL;DRs (warnings).
- **Doc templates** are in `_templates/` (one per type: call, dossier, decision, spec, audit, inventory). Every library doc has frontmatter with `type`, `status`, `group`, `owner`, `date`, `last_reviewed`, and `sources`.

## Status legend

Frontmatter `status` is one of four values. Every library doc uses one of them.

| Status | Meaning | Cite it? |
|---|---|---|
| **draft** | Not yet reviewed. Do not cite as current fact. | No |
| **current** | Maintained, or a reference whose sources still hold. Check `last_reviewed`. Partly superseded docs are current with a `caveat` line. | Yes, with the date |
| **superseded** | Replaced. `replaced_by` names the doc that replaces it. Lives in `archive/superseded/`. | Only as history |
| **archived** | Pre-rebuild snapshot of the old site or old drafts. Lives in `archive/snapshots/`. | Only as history |

Doc `type` (call, dossier, decision, spec, audit, inventory) says what the doc is for. Asset inventories are `inventory`.

## Conventions for new documents

1. Add frontmatter to every library doc: `status` (current, reference, partly-superseded, snapshot, superseded, or asset) and `group` (the top folder). `python3 scripts/discovery_check.py check` enforces this.
2. Name the file for its topic. Put a date in the name only for calls and decisions.
3. Use relative links. Never absolute paths. `scripts/discovery_check.py check` validates them.
4. Do not copy route lists or facts that another file owns. Link to the owner (`routes.ts`, an ADR, `knowledge_base/uwc_kb_v1.md`).
5. When a document is superseded, change its status to `superseded` or `partly-superseded`, add a banner that names the replacement, and move it to `archive/`. Do not delete it.
6. After adding or changing docs, run `python3 scripts/discovery_check.py manifest` to refresh `manifest.json`.
